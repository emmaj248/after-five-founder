# Implement the After Five Founder visual target — not a redesign from imagination

Act as a senior frontend engineer implementing an approved visual specification. Read every file in `design/after-five-target/` before touching code. Open `03-reference.html` in a browser and inspect it at 1440x900 and 390x844. This is a concrete composition target, not a suggestion to invent another design. The target is a bright, warm, founder-led technology journal: editorial typography, real software visuals, restrained bronze accents and human observations. It is neither a beige lifestyle blog nor an AI news portal.

## Phase A: baseline and assets
Inspect the actual repository, routes, current homepage, assets, styles, content pipeline and calculator contracts. Capture baseline full-page desktop and mobile screenshots. Locate exact approved logo, existing font files, authentic founder portrait, playful hero graphics, published article assets, calculator UI and newsletter form. Write a short asset mapping with exact paths. Do not regenerate logo or portrait. Do not replace the original hero illustration with stock imagery. Preserve original approved copy where the reference uses illustrative wording. No third-party logos or imitated marks; use plain names and generic licensed icons only. Do not modify Scout, Studio, APIs, data, publishing or subscriptions.

## Phase B: implement homepage only
Use the reference HTML as a layout blueprint; port its structure and CSS into the existing framework, not an iframe or screenshot. Preserve original logo and existing Bodoni/Jost fonts. Use white/paper as dominant surface; cream only as contrast. Use the CSS tokens for sizing, spacing and layout. Avoid a site-wide beige wash, pill overload, generic card grid, oversized hero and excessive padding. Hero must retain original playful technology storytelling: invoices, software subscriptions, AI questions and handwritten observations. Map real existing components into the right-hand composition. Use crisp foreground interfaces with subtle depth and no heavy filters. Keep heading on three lines on desktop as in reference; no forced wrapping at mobile. Preserve primary tagline. Keep founder visible immediately after editorial feed; real photo only. Move published stories higher, use one feature and two smaller stories; if none exist render honest compact empty state. Showcase actual calculator UI and preserve logic. Keep existing themes/building-in-public, shop availability, and newsletter functionality. Do not invent content or commercial claims. Do not change navigation routes unnecessarily. No production deploy.

## Phase C: visual verification, mandatory
Use existing browser tools or Playwright if available; install nothing without approval if not already available. Capture actual staging and reference at identical viewports. Follow `04-visual-qa.md`. Compare screenshots side by side, not just DOM or build output. Iterate on spacing, proportions, color and hierarchy until all critical checks pass. Where authentic assets differ from placeholders, compare bounding boxes and composition rather than literal pixels. Do not claim fidelity if browser tooling is unavailable. No broad redesign of unrelated pages. No new paid calls. Record changes and screenshot paths.

## Deliverables
Return working staged implementation, before/after screenshots at desktop and mobile, completed visual checklist with evidence, asset mapping and any unresolved discrepancies. Stop before production deployment. If you cannot render or access assets, report blockers explicitly and preserve existing working elements. Do not call work complete merely because the build passes.
